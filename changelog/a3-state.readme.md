Supported subset: `[*]` start/end pseudostates (scoped — a composite gets its own), transitions `A --> B : label`, bare-id state declarations, `state "Long title" as id`, description lines `id : text` (the first replaces the id as the label, later ones stack), composite `state X { ... }` blocks with nesting, per-composite `direction`, transitions to/from a composite box itself (forward references included), `<<choice>>` (a compact diamond whose branch labels stack in rows by their targets; in `TB`/`BT`, labels too wide for rows spread the targets apart; two transitions to one state put their labels either side of the pair) and `<<fork>>` / `<<join>>` (bars laid across the flow and stretched to span their branches, which drop straight onto their states). Notes are drawn as mermaid draws them: `note right of X : text`, `note left of X : text` and the `note right of X` … `end note` block become a yellow card joined to the state by a dotted line, one layer after (`right of`) or before (`left of`) the state along the flow, inside the state's composite. A card wholly to one side of its state is linked from the side facing it, unless that would cross one of the state's transitions. A note on a composite links to its frame; a note beside a fork/join bar sits past its branches. `note "text" as N` is a free-standing card (mermaid drops it). Note cards are ordinary nodes, so they can be picked and dragged like states. Not yet: concurrency regions (`--`), entry/exit actions. See `examples/state.mmd`.
