fix(blocks): in a TD/BT block layout a leg a clearance inside a frame's wall no longer reads as riding it (b12a2b-base item 4a, lateral X2)

`router::side_run` counts a run within `CLEAR_GAP` of a frame border or
node side as riding it (the repair's `hug`). In a block layout a frame
grown over an inner leg (B12 2.7 F3) stands exactly `LANE_PAD` (=
`CLEAR_GAP`) off the leg's column, and the simplified path's rounded
corner puts the leg's middle a fraction of a pixel nearer: a long chain
column beside a block's wall scored as riding it beyond `HUG_TRADE`, the
labelled edge was searched for room and left the block through that
wall. In a TD or BT block layout a run beside a frame's border now
counts only within
`CLEAR_GAP - HUG_AIR` (half a pixel, the air `ortho::TRACK_PITCH` adds to
a stroke's clearance); a node's side keeps `CLEAR_GAP`, and outside a
block layout nothing changes (`World::hug_gap`, set in `repair`).

The lateral study's form of the fix (F3 grows a frame over an inner leg
by `LANE_PAD + 0.5`) was measured first and not taken: it moves frames
by half a pixel, which makes 13 already-failing `compact_max` cells of
the local judge worse by 0.01 (local acceptance inputs, the public fixture
family, bench-75, dense-lr) that nothing in this package pays back, and with it
(as with this rule in all four directions) dense-td drawn RL gains a
crossing (29 -> 30) and a 290 px run along a frame. Applied to frame
borders in TD and BT only, neither happens.
