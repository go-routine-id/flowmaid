1Ringkasan

Chat service yang sudah ada mendapat satu kemampuan baru: menerima permintaan "vibe coding" dan menjalankannya lewat Claude Code di container kita sendiri. Pengguna mengetik di chat, agen bekerja di sandbox, lalu jawaban dan progresnya mengalir kembali ke thread yang sama.

Apa yang dibangun

  • Session orchestrator — menghubungkan thread chat dengan sesi agen dan sandbox-nya, lalu meneruskan jawaban agen ke chat service secara streaming.
  • Sandbox runner pool — kumpulan container siap pakai yang berisi Claude Agent SDK, CLI claude, dan toolchain untuk build.
  • Event gateway — menerima event dari agen (tugas selesai, butuh izin, error) lewat hook http, lalu meneruskannya ke notif service.
  • Secret vault dan egress proxy — API key dan token git diberikan per sesi; semua koneksi keluar lewat daftar domain yang diizinkan.
  • flowmaid — diagram mermaid yang ditulis agen tampil interaktif di chat, dan hasil editannya dikirim kembali ke agen sebagai teks.

4Komponen baru

Session orchestrator

  • API: POST /sessions, kirim pesan, interrupt, dan keputusan izin.
  • Menyimpan pasangan thread, sesi, dan sandbox (Redis atau Postgres).
  • Meneruskan event ke chat service lewat gRPC stream atau SSE.
  • Menulis event log ke storage service dan mengecek kuota ke account service.

Sandbox runner pool

  • Pod hangat yang siap dipakai; mulai dari 1 vCPU dan 1 GiB per agen.
  • Image berisi Agent SDK, CLI claude, git, dan toolchain build.
  • NetworkPolicy: koneksi keluar hanya ke egress proxy; ResourceQuota per tenant.
  • Idle terlalu lama → ditangguhkan; melewati TTL → dihapus.

Agent runtime (Claude Agent SDK)

  • query() atau ClaudeSDKClient dengan output streaming.
  • resume dengan session_id untuk melanjutkan percakapan.
  • canUseTool meneruskan permintaan izin ke chat.
  • Konfigurasi per sesi: folder kerja sendiri, tanpa login akun pribadi.

Event gateway

  • Menerima hook http: Stop, SubagentStop, TaskCompleted, Notification.
  • Event PostToolUse dicatat ke audit log.
  • Setiap sesi punya token; event tanpa token ditolak.
  • Meneruskan ke thread chat dan ke notif service.

Secret vault

  • API key Claude per tenant dan token git per pengguna.
  • Diberikan ke sandbox saat sesi dimulai, dicabut saat sandbox dilepas.
  • Tidak pernah masuk ke prompt, transkrip, atau log.

Egress proxy

  • Daftar domain yang diizinkan: API Anthropic, git host, registry paket.
  • Log per sesi, batas bandwidth dan jumlah koneksi.
  • Domain baru ditambah lewat konfigurasi tenant, bukan oleh agen.

flowmaid render

  • Di klien: modul WASM merender blok mermaid dalam pesan agen menjadi diagram interaktif.
  • Di server: library yang sama menghasilkan SVG untuk notifikasi, email, dan pratinjau link.
  • Mendukung 13 jenis diagram, antara lain flowchart, sequence, class, state, ER, gitGraph, architecture, dan mindmap.
  • Tema bisa mengikuti aplikasi: palet bawaan flowmaid, atau tema neutral, dark, dan forest.

5Alur utama

5.1 Mengirim prompt dan menerima jawaban secara langsung

Chat service meneruskan prompt beserta session_id. Orchestrator memanggil agen dengan resume, sehingga konteks percakapan sebelumnya ikut terbawa. Jawaban mengalir kembali sebagai potongan teks dan langsung tampil di thread. Di akhir giliran, agen mengirim ringkasan hasil berisi biaya dan pemakaian token untuk keperluan metering.

5.2 Izin tool di dalam chat

Sebelum agen menjalankan perintah yang berisiko — misalnya menjalankan perintah shell, menulis file di luar workspace, atau membuka akses jaringan baru — SDK memanggil canUseTool. Orchestrator menahan proses itu, dan chat service menampilkan kartu dengan pilihan setujui atau tolak. Mode izin bisa diatur per tenant: default, acceptEdits, atau plan untuk meninjau rencana sebelum dijalankan.

5.3 Tugas di latar belakang dan notifikasi

Tugas yang panjang — build, test suite, sub-agent — tetap berjalan walaupun pengguna menutup aplikasi. Saat tugas selesai, hook TaskCompleted atau Stop mengirim event ke event gateway. Gateway mencocokkan sesi dengan penggunanya, menampilkan event di thread chat, dan meminta notif service mengirim push. Email hanya untuk ringkasan, bukan untuk setiap event.

5.4 Siklus hidup sesi

Sesi dan sandbox punya umur yang berbeda. Sandbox boleh mati — karena idle terlalu lama, node di-drain, atau crash — tanpa kehilangan percakapan.

  • Warm: container sudah hidup di pool, belum dipakai siapa pun.
  • Running / Waiting: agen sedang bekerja, atau menunggu izin di chat.
  • Idle: giliran selesai; sandbox masih terpasang supaya balasan berikutnya cepat.
  • Suspended: sandbox dilepas; event log dan snapshot workspace tersimpan di storage service.
  • Resume: prompt baru mengambil sandbox baru, memulihkan workspace, lalu memanggil agen dengan resume.
  • Reclaimed: TTL habis; data dihapus sesuai kebijakan retensi.
Catatan: format file transkrip milik CLI bersifat internal dan bisa berubah antar versi. Simpan event dari output SDK atau stream-json, jangan mem-parse file transkripnya.

6flowmaid di dalam chat

Vibe coding sering memakai diagram: alur API, skema data, state machine, urutan deploy. Agen menulis blok mermaid, chat merendernya dengan flowmaid, dan pengguna bisa langsung menggeser node. Hasil editan dikirim kembali ke agen sebagai teks mermaid, sehingga agen membaca diagram yang sama dengan yang dilihat pengguna.

Kenapa flowmaid

  • Tanpa dependency: satu crate Rust yang bisa dikompilasi ke WASM tanpa runtime JavaScript yang besar.
  • Interaktif: scene untuk tata letak, route_partial saat node digeser, hit_test untuk memilih elemen, to_mermaid untuk menyimpan.
  • Deterministik: input yang sama selalu menghasilkan SVG yang sama, sehingga aman untuk cache dan snapshot test.
  • Satu sumber geometri untuk tampilan di layar, thumbnail, dan ekspor SVG.

Garis besar integrasi

// Klien (WASM): render blok mermaid dari pesan agen
let g     = parse(src)?;
let scene = scene::scene(&g);

// Saat node digeser: hanya edge yang terdampak dihitung ulang
route_partial(&g, &scene, moved);
let hit = scene.hit_test(x, y);

// Simpan: kembalikan ke agen sebagai teks mermaid
let text = to_mermaid(&g);

// Server: SVG untuk notifikasi dan email
let svg = render_svg_advanced(src, &opts)?;

Nama fungsi sesuai README flowmaid; signature lengkapnya ada di dokumentasi crate.

Status flowmaid: sedang di fase B (paket 7 dari 13). Diagram di dokumen ini dirender dengan build dev hari ini. Rilis 0.34.0 menyusul setelah fase B dan C selesai.

7Keamanan dan isolasi

  • Satu sandbox per sesi. Filesystem, proses, dan environment tidak dibagi antar pengguna. Runtime seperti gVisor atau Kata Containers menambah lapisan pengaman di atas container biasa.
  • Jaringan tertutup. Semua koneksi ditolak secara default; koneksi keluar hanya lewat egress proxy dengan daftar domain per tenant.
  • Rahasia tidak pernah jadi teks. API key dan token git disimpan di vault, diberikan saat sesi dimulai, dan dicabut saat sandbox dilepas.
  • Izin yang jelas. canUseTool dan mode izin per tenant, ditambah aturan penolakan untuk perintah berbahaya.
  • Audit. Setiap pemakaian tool dan keputusan izin dicatat beserta session_id dan penggunanya.
  • Lisensi dan autentikasi. Produk yang melayani pengguna lain wajib memakai API key (Claude Console, Bedrock, atau Vertex) di bawah Commercial Terms. Login langganan Free/Pro/Max tidak boleh dipakai atas nama pengguna, dan binary Claude Code tidak boleh dimodifikasi.

9Skala dan biaya

  • Ukuran awal: 1 vCPU dan 1 GiB per agen, sesuai titik awal di dokumentasi hosting Agent SDK. Bisa dinaikkan per tenant untuk build yang berat.
  • Pool container hangat: jumlahnya mengikuti puncak sesi baru per menit, dengan target sandbox siap dalam kurang dari 2 detik.
  • Idle dan TTL: sandbox ditangguhkan setelah idle beberapa menit dan dihapus setelah TTL. Sesi tetap bisa dilanjutkan dari storage.
  • Biaya token: prompt caching otomatis menurunkan biaya konteks yang berulang. Orchestrator mengecek kuota dan batas biaya akun sebelum setiap giliran.
  • Observability: OpenTelemetry dari SDK — latensi, pemakaian token, pemakaian tool, dan kegagalan.

11Risiko dan pertanyaan terbuka

RisikoMitigasi
Biaya token melonjakBatas biaya per akun dan per sesi, peringatan di chat sebelum batas tercapai, dan model yang lebih ringan untuk tugas rutin.
Kode agen keluar dari sandboxRuntime terisolasi, jaringan tertutup, tanpa kredensial cloud di environment, dan egress proxy.
Format internal berubahHanya memakai SDK dan stream-json; versi SDK dan CLI dikunci di image; upgrade diuji di staging.
Container mati di tengah tugasEvent log dan snapshot workspace; sesi dilanjutkan otomatis di sandbox baru.
Kepatuhan lisensiAPI key per tenant atau milik pengguna; tidak ada login langganan yang dipakai bersama.

Pertanyaan terbuka

  • Bahasa orchestrator: Go (selaras dengan layanan yang ada) yang memanggil SDK TypeScript lewat sidecar, atau langsung memakai claude -p dengan stream-json?
  • API key: kunci milik platform dengan metering, kunci milik pengguna (bring your own key), atau keduanya?
  • Alternatif terkelola: Managed Agents (beta) dengan sandbox milik sendiri, untuk mengurangi kode orchestrator?
